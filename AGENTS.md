# Repository Guidelines

## Структура проекта

DomainMapper разрешает доменные имена в IP-адреса, агрегирует подсети и экспортирует маршруты для сетевых устройств.

- `main.py`: основной CLI, асинхронные DNS-запросы, фильтрация и экспорт.
- `merge_routes.py`: объединение маршрутов Keenetic с удалением дублей и покрытых подсетей.
- `platforms/`: списки доменов сервисов; `platformdb` и `dnsdb`: справочники сервисов и DNS-серверов.
- `utilities/`: поиск субдоменов, проверка доменов, преобразование и разбиение списков.
- `Windows/` и `utilities/win/`: Windows-обёртки и инструкции.
- Корневые `*.ini`: конфигурации; многочисленные `*.txt`: входные списки и результаты обработки. Проверяйте назначение файла перед изменением.

## Установка и запуск

Выполняйте команды из корня репозитория:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python main.py
python main.py -c keen-config.ini
python merge_routes.py domain-ip-custom.txt domain-ip-youtube.txt -o /tmp/merged-routes.txt
```

`main.py` использует `config.ini`, если другой файл не передан через `-c`. Последняя команда объединяет подготовленные маршруты в отдельный файл. Отдельного этапа сборки нет. Перед запуском вспомогательных скриптов прочитайте `utilities/README.md`: некоторые утилиты перезаписывают входные файлы.

## Стиль кода и данных

Используйте четыре пробела для отступов Python, `snake_case` для функций и переменных, `PascalCase` для классов. Сохраняйте стиль окружающего кода и ограничивайте изменения поставленной задачей. Настройки форматтера и линтера в репозитории отсутствуют.

Доменные списки содержат один домен на строку без схемы URL и пути. Для списков сервисов следуйте существующим именам `platforms/dns-*.txt`. Сохраняйте результаты в UTF-8 без BOM. Пишите комментарии и пояснения по-русски; используйте обычный дефис вместо длинного тире.

## Проверка изменений

Автоматизированного набора тестов и порога покрытия нет. Проверяйте синтаксис изменённых модулей, например:

```bash
python -m py_compile main.py merge_routes.py
```

Для изменений объединения маршрутов используйте временные файлы с дублями, вложенными подсетями и некорректными строками; сравнивайте результат с ожидаемым. Для DNS и экспорта выполните небольшой прогон с отдельной конфигурацией и проверьте формат результата. Укажите использованные команды и ограничения сетевой проверки в PR.

## Коммиты и pull request

История использует короткие сообщения вроде `Update dns-youtube.txt` и `Fix #113`; обязательного формата Conventional Commits нет. Описывайте конкретное изменение и добавляйте номер обращения, когда он есть. Не добавляйте трейлеры соавторства.

В PR укажите проблему, изменённое поведение, затронутые конфигурации и выполненные проверки. При изменении формата маршрутов приложите небольшой пример входа и выхода. Не включайте случайно изменённые локальные результаты.

## Конфигурация

Перед запуском проверяйте выходные пути и команды, выполняемые после обработки. Для локальных справочников задайте `localplatform = yes` и `localdns = yes`; названия сервисов и номера DNS должны соответствовать конфигурации. Не публикуйте секреты и приватные сетевые параметры.
